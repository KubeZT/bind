Developer Cluster Onboarding

Bind your workstation to a KubeZT cluster.

Binding prepares your local environment to reach a KubeZT enclave through verified identity, scoped artifact access, and a cluster-specific Kubernetes context.

One command. One context. Ready to operate.

The bind flow installs the local helpers it needs, downloads approved cluster artifacts, activates the kubeconfig, and exposes the KubeZT administrator command in the current terminal.

01

Install OpenZiti

Install the OpenZiti client for your platform so your workstation can reach private KubeZT services.

02

Enroll Identity

Load the identity provided by your administrator and confirm the client is connected.

03

Run Bind

Run the bind command, enter the access keys provided to you, and start using kubectl.

Activation Command
source <(curl -fsSL https://bind.kubezt.com) <cluster-name> kubezt status kubectl get nodes

What Bind Configures

  • A cluster AWS profile in ~/.aws/credentials when needed.
  • Cluster artifacts in ~/.kubezt/clusters/<cluster>.
  • A local KUBECONFIG pointing at <cluster>.config.
  • The kubezt command and compatible kubectl tooling.

Before You Start

  • OpenZiti client is installed and running.
  • Your identity is enrolled and available on the workstation.
  • You have the cluster name and read-only artifact access keys.
  • Your terminal is Bash or Zsh on macOS or Linux.
Independent. Secure. Interoperable.
Bind establishes local access without exposing the cluster control plane to the open network.
