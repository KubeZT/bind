Get bound to a KubeZT cluster.

Bind turns a new workstation into a cluster-ready developer environment: identity-based network access, approved artifacts, kubeconfig, kubectl, and the KubeZT command line in one guided flow.

Developer Cluster Onboarding

Access without local guesswork.

The bind tool pulls the cluster-specific files, validates the kubeconfig, sets the active context, and leaves the developer ready to run kubezt status or kubectl get nodes.

01

Install OpenZiti

Install the client for your platform so private KubeZT endpoints are reachable from your workstation.

02

Enroll Identity

Load the identity provided by your administrator and confirm the client is connected.

03

Run Bind

Run the command, enter the provided artifact access keys, and activate the cluster in your shell.

Developer Command
source <(curl -fsSL https://bind.kubezt.com) <cluster-name> kubezt status kubectl get nodes

What Bind Sets Up

  • A named AWS profile for cluster artifact downloads.
  • Cluster files under ~/.kubezt/clusters/<cluster>.
  • KUBECONFIG pointed at the downloaded cluster config.
  • The kubezt command and compatible local kubectl tooling.

What You Need

  • OpenZiti client installed and running.
  • Your enrolled KubeZT identity on the workstation.
  • The cluster name and artifact access keys from your administrator.
  • Bash or Zsh on macOS or Linux.
